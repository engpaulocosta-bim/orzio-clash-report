# Security and private-data reporting

Do not post credentials, private exports/models, identifiable reports or exploit details
in public issues. Use this repository's **Security > Report a vulnerability** private
reporting flow when available. If it is unavailable, open a minimal issue asking the
maintainer to enable private reporting, without including sensitive details or attachments.

Report the affected version, impact and a minimal synthetic reproduction. No response-time
or supported-version guarantee is offered for this preview.

If a credential is exposed, revoke/rotate it at its issuer first. History rewriting cannot
revoke credentials or remove copies already downloaded. Coordinate history sanitation
with maintainers; never merge or push an old clone back into a cleaned repository.
